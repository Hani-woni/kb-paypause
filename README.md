## 💡 서비스 소개

**KB PayPause**는 헬스장·PT 등 장기 선결제 계약 전에  
계약조건, 업체 영업지속 상대위험, 예상 환급액, 결제수단별 선불 노출액을 함께 분석하여  
소비자가 충분히 검토한 뒤 계약과 결제방식을 선택하도록 돕는 사전예방 서비스입니다.

---

## 🚨 문제 정의

장기 선결제 계약에서는 다음 위험을 소비자가 결제 전에 파악하기 어렵습니다.

- **불리한 계약조건**: 환불불가, 과도한 위약금, 정상가 기준 차감
- **업체 영업중단 위험**: 휴업·폐업 시 잔여 이용금액 회수 어려움
- **결제수단별 보호 차이**: 현금·일시불·할부에 따라 선불 노출금액과 소비자 보호수단이 달라짐

기존 서비스는 계약서 검토, 환불 계산, 업체 정보, 카드 혜택을 각각 제공하지만  
이를 결제 전 하나의 판단 과정으로 연결하는 데 한계가 있습니다.

## 🏗️ 전체 시스템 구조

```text
계약서 PDF·이미지 및 업체정보 입력
                ↓
        OCR 및 계약정보 구조화
                ↓
 ┌──────────────────────────────────┐
 │ 업체 영업지속 상대위험 분석        │
 │ 규칙기반 계약서 위험조항 분석      │
 │ 환급액·결제수단 위험 비교          │
 └──────────────────────────────────┘
                ↓
          최종 통합 판단
                ↓
 계약 진행 / 조건 수정 / 결제 보류
                ↓
       Streamlit 결과 화면
```

## ✨ 핵심 기능

### 1. 계약서 OCR 및 정보 구조화

사용자가 계약서 PDF 또는 이미지를 업로드하면 다음 정보를 자동으로 추출합니다.

- 사업자명 및 주소
- 실제 계약금액
- 현금 할인가
- 정상가 또는 할인 전 가격
- 월 이용료
- 계약기간
- PT 총 횟수
- 위약금률
- 환급 공제 기준
- 결제수단 및 할부개월

텍스트가 포함된 PDF는 `PyMuPDF`로 직접 추출하고, 스캔 PDF와 이미지 파일은 `EasyOCR`로 처리합니다.

확인되지 않은 값은 임의로 `0`이나 `False`로 변환하지 않고 `None`으로 유지하며, 최종 계산 전 사용자가 추출 결과를 직접 확인할 수 있도록 구성했습니다.


### 2. 불공정 의심조항 탐지

계약서 원문과 추출된 정보를 함께 분석하여 다음과 같은 위험·확인 항목을 탐지합니다.

| 위험 유형 | 주요 내용 |
|---|---|
| 정상가 기준 공제 | 실제 결제금액이 아닌 할인 전 정상가로 이용분 차감 |
| 환불 전면 제한 | 이벤트·프로모션 상품 등의 중도해지 및 환불 제한 |
| PT 정상가 공제 | 실제 결제단가가 아닌 회당 정상가 기준 공제 |
| 복수 비용 공제 | 위약금·할인액·수수료·사은품 가액 등을 중복 공제 |
| 추가 납부 요구 | 환불액 부족 시 소비자에게 추가 비용 요구 |
| 환불 신청 제한 | 특정 시간 방문 또는 서면 접수만 허용 |
| 휴회 사유 제한 | 임신·출장·시험·이사 등의 사유를 일률적으로 제외 |
| 트레이너 변경 시 환불 제한 | 트레이너 변경·퇴사·일정조정 시 환불 거부 |
| 폐업 시 현금환불 제한 | 휴업·폐업·지점 이전 시 현금환불 또는 선택권 제한 |
| 사업자 책임 면제 | 사고·부상·분실에 대한 사업자 책임 전면 면제 |
| 일방 해지 후 미환급 | 사업자 판단으로 계약을 종료하고 잔여금 미반환 |
| 전속 관할 지정 | 사업자 소재지 법원을 전속 관할로 지정 |
| 횟수 자동 차감 | 지각·노쇼·당일취소를 1회 이용으로 처리 |

실제와 유사하게 제작한 3페이지 헬스장·PT 테스트 계약서에서 의도적으로 포함한 13개 위험·확인 항목을 모두 탐지했습니다.

> 위험 항목이 탐지되지 않았다는 결과는 계약의 법적 안전을 확정하는 의미가 아닙니다.  
> 서비스에서는 이를 “자동 탐지된 위험 없음”으로 표현합니다.


### 3. 환급액 비교

계약서에 적힌 환급방식과 공식 기준 참고방식을 각각 계산하여 차이를 보여줍니다.

```text
공식 기준 참고 환급액
= 실제 결제금액 - 이용분 - 적용 가능한 위약금
```

서비스는 다음 정보를 제공합니다.

- 계약서 기준 환급액
- 공식 기준 참고 환급액
- 두 기준 간 예상 불이익
- 계산에 사용한 계약기간 및 사용기간
- 적용한 위약금 기준

예시:

```text
실제 계약금액: 1,200,000원
정상가: 1,800,000원
계약기간: 12개월
사용기간: 1개월

계약서 기준 환급액: 930,000원
공식 기준 참고 환급액: 980,000원
예상 불이익: 50,000원
```

금액 계산은 생성형 AI에 맡기지 않고 공식 기준을 반영한 결정론적 계산 로직으로 수행합니다.


### 4. 결제수단별 선불 노출액 비교

같은 계약이라도 결제수단에 따라 소비자가 미리 부담하는 금액과 보호 가능성이 달라집니다.

KB PayPause는 현금·계좌이체를 기준으로 카드 일시불, 카드 할부, 월 단위 결제의 선불 노출액을 비교합니다.

| 결제수단 | 선불 노출액 예시 |
|---|---:|
| 현금·계좌이체 | 1,080,000원 |
| 카드 일시불 | 1,200,000원 |
| 카드 6개월 할부 | 200,000원 |
| 월 단위 결제 | 120,000원 |

```text
현금 대비 위험 감소액
= 현금 선불 노출액 - 해당 결제수단의 선불 노출액
```

카드 할부와 관련된 소비자 보호 가능성은 자동으로 확정하지 않고, 금액·할부기간·서비스 미제공 여부 등 확인해야 할 조건을 함께 안내합니다.


### 5. 업체 영업정보 및 상대위험 분석

행정안전부 지방행정인허가데이터의 체력단련장업 기록을 활용하여 업체를 검색하고, 공개 인허가 및 지역 영업이력에 기반한 상대위험 정보를 제공합니다.

#### 활용 데이터

- 전국 체력단련장업 인허가 기록 27,761건
- 사업장명
- 인허가일자
- 폐업일자
- 영업상태
- 주소
- 지역별 개·폐업 이력
- 동일 주소 과거 폐업이력

`CatBoostClassifier`를 활용하여 개업 후 2년 이내 폐업 여부를 학습했습니다.

| 지표 | 테스트 결과 |
|---|---:|
| PR-AUC | 0.0794 |
| 무작위 PR-AUC 기준 | 0.0533 |
| ROC-AUC | 0.6055 |
| Precision | 0.0816 |
| Recall | 0.0874 |
| F1-score | 0.0844 |

모델의 구분력이 개별 업체의 미래를 확정할 수준은 아니므로 원시 예측값을 폐업확률로 표시하지 않습니다.

대신 전체 기준집단 내 위치를 계산해 **동일 업종 내 상대적 영업지속 위험 백분위**로 제공합니다.

```json
{
  "relative_risk_percentile": 82.0,
  "risk_level": "caution"
}
```

이는 “폐업확률 82%”가 아니라, 공개 인허가 특성에 기반한 위험점수가 비교집단의 약 82백분위에 위치한다는 의미입니다.

관찰기간이나 모델 입력정보가 부족한 업체는 임의의 위험값을 생성하지 않습니다.

```json
{
  "relative_risk_percentile": null,
  "risk_level": "check_required"
}
```

## 🚦 최종 판단

계약서 위험, 업체 영업지속 상대위험, 예상 환급손실, 결제수단별 선불 노출액을 종합하여 최종 결과를 세 단계로 제공합니다.

| 내부 상태 | 사용자 화면 |
|---|---|
| `payable` | 계약 진행 |
| `revise` | 조건 수정 후 진행 |
| `hold` | 결제 보류 권고 |

최종 결과와 함께 다음 행동도 안내합니다.

- 계약서에서 수정해야 할 조건
- 사업자에게 확인할 질문
- 환급기준 수정 요청 문구
- 결제수단 변경 제안
- 추가 확인이 필요한 정보

현재 정책 점수와 임계값은 프로토타입 단계의 기준이며, 향후 실제 소비자 피해데이터와 전문가 검토를 통해 보정할 예정입니다.

## 🧠 설계 원칙

### AI와 결정론적 로직의 역할 분리

AI와 자동화 기술이 필요한 부분:

- 다양한 형식의 계약서에서 정보 추출
- 계약 문구와 위험 표현 분석
- 분석 결과를 이해하기 쉬운 형태로 제공

AI에 맡기지 않는 부분:

- 환급액 계산
- 위약금 계산
- 결제수단별 선불 노출액 계산
- 최종 정책 점수 계산

금액과 기준 계산은 동일한 입력에 대해 항상 동일한 결과가 나와야 하므로 규칙 기반의 결정론적 로직으로 구현했습니다.

### 확인되지 않은 값은 생성하지 않음

확인되지 않은 금액·기간·횟수는 `0`으로 처리하지 않고 `None`으로 유지합니다.

분석에 필요한 값이 부족한 경우 임의 계산 대신 사용자 확인 또는 `check_required` 상태를 반환합니다.

### 단정적인 표현 제한

다음과 같이 특정 업체나 계약의 결과를 확정하지 않습니다.

```text
이 업체는 2년 이내 폐업합니다.
이 계약은 법적으로 무효입니다.
카드 할부를 하면 반드시 보호받습니다.
```

대신 다음과 같이 참고정보로 제공합니다.

```text
공개 인허가 및 지역 영업이력 기준 상대위험 참고값입니다.
공식 기준과 비교했을 때 확인이 필요한 조항입니다.
카드사에 보호요건 적용 여부를 확인할 필요가 있습니다.
```

## ▶️ 실행 방법

### 1. 저장소 복제

```bash
git clone https://github.com/Hani-woni/kb-paypause.git
cd kb-paypause
```

저장소 내부에 동일한 이름의 하위 폴더가 있는 경우:

```bash
cd kb-paypause
```

### 2. 가상환경 생성

#### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

#### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. 패키지 설치

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

EasyOCR는 최초 실행 시 한국어 인식 모델 다운로드 및 로딩 시간이 발생할 수 있습니다.

### 4. Streamlit 실행

```bash
streamlit run app.py
```

기본 접속 주소:

```text
http://localhost:8501
```

## ⚠️ 한계점

- 규칙과 정규표현식만으로 실제 계약서의 모든 표현을 포괄할 수 없습니다.
- 저해상도, 기울기, 그림자, 손글씨가 있는 계약서는 OCR 정확도가 낮아질 수 있습니다.
- 계약서에 헬스와 PT의 항목별 실제 결제금액이 없으면 결합형 환급액을 정확히 분리하기 어렵습니다.
- 업체 분석 모델은 매출, 임대료, 부채, 현금흐름, 회원 수 변화 등의 정보를 사용하지 못합니다.
- 업체 모델은 개별 폐업을 확정할 수준이 아니므로 상대위험 참고값으로만 제공합니다.
- 최종 정책 점수와 가중치는 프로토타입 기준이며 전문가 검토와 실제 피해데이터를 통한 보정이 필요합니다.
- 본 서비스의 결과는 법률 자문이나 분쟁 결과를 보장하지 않습니다.
